# Third-party integrations

Alehouse supplies the orchestration code, not a second Pi runtime. The lockfile pins source-development dependencies; the launcher uses the operator's host Pi. [Third-party notices](../THIRD_PARTY_NOTICES.md) contains the copyright notices and reproduced MIT texts.

| Project                                                                                                                         | Relationship to Alehouse                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Pi](https://github.com/earendil-works/pi)                                                                                      | Supplies the SDK sessions, model registry, extension events and terminal components. The host implementation is not forked. Pinned development SDKs exercise these interfaces; they are not a host-version allowlist.                                                             |
| [pi-permission-system](https://github.com/gotgenes/pi-packages/tree/pi-permission-system-v32.0.3/packages/pi-permission-system) | The build patches a **private copy** of the pinned authority. Parent and child sessions use that same authority, including Alehouse's deny-only protection for runtime and credential paths. The generated vendor directory must retain the upstream `LICENSE`.                   |
| [pi-web-access](https://github.com/nicobailon/pi-web-access)                                                                    | Loaded from the package's pinned dependency, not from an ambient Pi extension. The parent integration and each active scout use separate module instances; the scout gets a restricted tool surface. See [web access and data handling](security.md#researcher-web-access).       |
| [pi-subagents](https://github.com/gotgenes/pi-packages/tree/b3b6159399f541fd0623f65818557dd3e707a34f/packages/pi-subagents)     | A design reference, **not** a runtime dependency. Alehouse follows its child lifecycle ordering, event vocabulary, widget glyphs, overflow/linger conventions and docked transcript approach. The scheduler, manager, tools and rendering code here are Alehouse implementations. |

Consult [architecture](architecture.md) for ownership boundaries and [development](development.md) before changing pins or the generated authority. Neither upstream UI conventions nor the name of a worker profile confer permission.
